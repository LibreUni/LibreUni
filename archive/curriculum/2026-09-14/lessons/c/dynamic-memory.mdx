# Dynamic Storage and Ownership

Dynamic storage solves a lifetime problem: an object must outlive the block that created it, or its size is known only at run time. It does not solve ownership automatically. Every allocated block still needs one responsible owner, a valid extent, and exactly one eventual release.

## Allocation is a contract

`malloc(bytes)` returns uninitialized storage or a null pointer. `calloc(count, size)` also has an integer-product overflow obligation: a wrapped product can allocate fewer bytes than the caller believes. Use checked multiplication when dimensions come from untrusted input. `free(NULL)` is a no-op, but that convenience is not a substitute for tracking ownership.

```c
int *values = malloc(count * sizeof *values);
if (values == NULL) {
    return OUT_OF_MEMORY;
}
```

The `sizeof *values` form follows the pointed-to type if the declaration changes. The caller must still prove `count * sizeof *values` fits in `size_t` before multiplication.

## Failure-safe `realloc`

`realloc(p, new_size)` may return the same address, move the allocation, or return null while leaving the original allocation live. Assigning directly to the only owner leaks on failure:

```c
int *grown = realloc(values, new_count * sizeof *values);
if (grown != NULL) {
    values = grown;
    count = new_count;
} else {
    /* values is still owned and can still be freed. */
}
```

If `new_size` is zero, portability and implementation behavior require deliberate handling; do not use a zero-size request as an implicit ownership protocol.

## Three failure modes, three proofs

- A **leak** loses the only pointer before release; the resource remains allocated but unreachable.
- A **use-after-free** accesses an object after its lifetime ends. The allocator may have reused the bytes for a different object.
- A **double free** releases the same allocation twice; allocator metadata or another component may be corrupted.

Set a local owner to `NULL` after transferring or releasing it, but nulling one copy does not invalidate aliases. A robust interface states whether a function borrows a pointer for the call, takes ownership, or returns ownership to the caller.

### Diagnostic solutions

1. For example, `data == NULL` iff `capacity == 0`, `length <= capacity`, and `data` points to at least `capacity` live `int` objects when non-null. Document who owns `data`.
2. Release the first resource on the failure edge, or use a cleanup label whose guards record which resources were acquired. Each path must release exactly the resources it owns.
3. The allocator returns the base pointer as the ownership token. An interior pointer does not identify the allocation and is not a valid argument to `free`.
4. Check `count <= SIZE_MAX / sizeof *items` before multiplying; also check any later conversion to a narrower index type.
