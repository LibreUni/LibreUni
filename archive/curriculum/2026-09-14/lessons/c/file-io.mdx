# C Streams, Files, and Persistence Contracts

The `FILE *` interface abstracts a stream of characters or bytes, not a durable transaction. Opening, reading, writing, seeking, flushing, and closing each have contracts and failure modes. A successful `fwrite` means data was accepted by the stream; it does not by itself prove power-loss durability.

## Modes and ownership

`r` requires an existing file; `w` truncates or creates; `a` appends. The `b` modifier requests binary mode where the implementation distinguishes text translation. Always state whether the stored format is a byte protocol or a platform-native representation.

```c
FILE *input = fopen(path, "rb");
if (input == NULL) return IO_OPEN_FAILED;
```

The caller that successfully opens a stream owns the responsibility to close it on every path. `fclose` can report an output or flush failure; production code should decide whether that failure invalidates the operation.

## Input choices and bounded records

Use `fgetc` for characters, `fgets` for bounded lines, `fread`/`fwrite` for blocks, and formatted functions only with a grammar and width policy. `fgets(buffer, capacity, file)` reads at most capacity-1 characters and may retain a newline; callers must handle a line longer than the buffer rather than treating truncation as a complete record.

`fscanf` can leave malformed input unread and make recovery difficult. For external text, read a bounded line, parse it with an end pointer, and validate trailing characters.

## Positions, buffering, and binary records

`fseek`, `ftell`, and `rewind` operate under stream and mode restrictions; text-stream positions should be treated as opaque values suitable for returning to a saved position, not necessarily byte counts. `fflush` flushes an output stream, but the path from a library buffer to stable storage is platform-specific.

Writing a `struct` directly with `fwrite` can encode padding, alignment, endianness, and representation choices. A portable file format serializes fields explicitly with version and length information.

### Diagnostic solutions

1. The caller or function that opened it owns it and must close it on all later paths; cleanup must preserve the first error if close also fails.
2. If no newline appears before the buffer's terminator and EOF has not been reached, the record may continue. Consume the remainder or reject it according to the protocol.
3. Padding/alignment and endianness can differ; integer and floating representations or pointer fields may not be portable. Versioned field serialization is safer.
4. fflush transfers library-buffered bytes to the underlying stream according to its contract. Durable storage requires platform-specific synchronization and failure handling.
