# Functions, Contracts, and Call Frames

Functions are useful because they make a computation nameable and testable, not because every call necessarily creates a particular physical stack layout. The C language specifies parameter and return semantics; an optimizer may inline a call or keep values in registers while preserving those semantics.

## Declarations and definitions

A declaration tells the compiler the function's type; a definition supplies the body. A prototype is not optional documentation: it lets the compiler check conversions at each call site.

```c
int square(int x);        /* declaration */

int use_square(void) {
    return square(5);     /* checked against the prototype */
}

int square(int x) {       /* definition */
    return x * x;
}
```

The phrase “single-pass compiler” is a poor model. Implementations commonly perform several translation phases and may compile multiple translation units before linking. The portable lesson is simpler: a call needs an appropriate visible declaration, and a program needs one compatible definition for the externally linked function.

## Value semantics and observable mutation

```c
void increment_value(int value) { ++value; }
void increment_object(int *value) { ++*value; }
```

`increment_value(x)` changes only a local parameter object. `increment_object(&x)` changes `x`, provided `&x` is valid and the caller permits mutation. The pointer itself is still passed by value; assigning a new address to `value` cannot rebind the caller's pointer.

## Automatic storage and recursion

An object with automatic storage duration is created when execution enters its block and ceases to exist when execution leaves it. Returning the address of a local object creates a dangling pointer; the bytes may remain unchanged in a debugger, but the object lifetime has ended.

Recursion adds a logical activation for each call. A recursive function needs a base case and a measure that moves toward it. Stack depth is an implementation resource, not a correctness proof: a mathematically terminating recursion can still exhaust a finite stack for a large input.

```c
unsigned factorial(unsigned n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}
```

## Transfer exercises

1. Write a prototype for a function that fills a caller-owned buffer and returns `0` on success or a negative error code.
2. Explain why returning `&local` is invalid even if the address prints consistently in one run.
3. Trace `f(&x)` when `f` assigns its parameter to point at a different object. Which pointer changes?
4. Replace a recursive countdown with an iterative loop and state the invariant.

### Diagnostic solutions

1. For example, `int fill(char *buffer, size_t capacity);` with a contract that writes at most `capacity` bytes and documents termination. The return convention must distinguish truncation or failure.
2. The pointed-to object has automatic storage duration and ends at function return. Reading through the pointer afterward is undefined behavior regardless of observed bytes.
3. The callee's parameter is a copy of the address, so only the local parameter changes. Mutating `*parameter` changes the pointed-to caller object.
4. Maintain “all values below the current counter have been processed”; decrement the counter until the base case is reached. The loop uses constant call-stack space.
