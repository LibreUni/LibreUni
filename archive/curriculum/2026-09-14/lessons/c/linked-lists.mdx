# Linked Lists, Invariants, and Ownership

A linked list trades contiguous storage and indexed access for local insertion and a representation that can grow node by node. The trade is worthwhile only when its update pattern or lifetime model justifies extra pointers, allocations, and cache misses.

## Representation and ownership

```c
struct node {
    int value;
    struct node *next;
};
```

A list with `head == NULL` is empty. A valid list has a finite acyclic chain from `head` to `NULL`; each reachable node is live and owned by the list. The list owner is responsible for destroying every reachable node exactly once. An external cursor is a borrow and must not free a node behind the list's back.

## Insertion and deletion

Head insertion is constant time because it changes two links:

```c
new_node->next = list->head;
list->head = new_node;
```

For deletion, save the successor before releasing the current node. If a list maintains a tail pointer or length, update those fields in the same operation or the invariant is broken. A failure to allocate must leave the old list unchanged; do not publish a partially initialized node.

## Cost and locality

Indexing the kth node costs Θ(k) pointer traversals. Inserting at a known node can be O(1), but finding that node is not. Nodes allocated far apart cause dependent loads and cache misses; an array or a growable vector may win even when both algorithms are O(n). Choose from a workload and mutation pattern, not an operation table alone.

## Transfer exercises

1. Prove that head insertion preserves acyclicity when the new node is freshly allocated and its next pointer is the old head.
2. Add a length field and list the updates needed for insert-empty, insert-nonempty, and delete-last.
3. Explain how a shared cursor becomes dangling after deletion.
4. Compare a list and a vector for repeated append followed by indexed reads.

### Diagnostic solutions

1. The new node points into the old finite acyclic chain and no old node points to the new node, so following next still reaches NULL without a cycle.
2. Increment/decrement length on successful mutation; set both head and tail for the first node; set both to NULL after deleting the final node.
3. The cursor designates an object whose lifetime ended. Invalidate cursors or use a stable-handle/reclamation protocol if external references are required.
4. A vector gives amortized constant append and constant indexed reads with locality. A list gives cheap insertion after a known node but linear indexed reads and allocation overhead.
