# Loops, Invariants, and Termination

A loop is a proof obligation repeated over a changing state. The reliable design sequence is: choose the state that summarizes processed work, establish it before the first iteration, preserve it, and show that a variant moves toward termination.

## `for`, `while`, and `do`

The three loop forms differ in when their condition is evaluated, not in the existence of a magical performance property:

```c
for (size_t i = 0; i < length; ++i) consume(values[i]);

size_t i = 0;
while (i < length) consume(values[i++]);

do {
    prompt();
} while (!valid_input());
```

Use `do` only when one execution is required before the test. Keep the update close to the condition it makes true; hidden mutation in a helper makes termination harder to audit.

## `break`, `continue`, and nested state

`break` exits the nearest loop; `continue` jumps to the loop's next condition/update point. In nested loops, name the level explicitly with a flag or a helper function rather than relying on a reader to track which loop is nearest. A loop that searches for a match often has two postconditions: found with a valid index, or exhausted with no match.

## Integer boundaries and termination

Unsigned integers wrap modulo one more than their maximum value. That can make a descending loop nonterminating:

```c
for (unsigned i = count; i >= 0; --i) { /* never ends */ }
```

The condition is always true for an unsigned value. Use a half-open index, test before decrementing, or choose a signed type only when its range and overflow are controlled. Signed overflow is undefined behavior, so “it eventually wraps” is not a valid proof.

## Transfer exercises

2. Repair the unsigned countdown above without reading outside the array.
3. Give a variant that proves a binary-search loop terminates.
4. Explain why a `continue` can accidentally skip an update and create a nonterminating loop.

### Diagnostic solutions

1. Before iteration i, `dst[j] == src[j]` for every `0 <= j < i`; the variant is `n - i`.
2. Use `for (size_t i = count; i-- > 0;) process(values[i]);`; the post-decrement test stops before i would be used as an invalid index.
3. The interval length `high - low` decreases whenever the loop continues, and the loop stops when the interval is empty.
4. If the update occurs after the `continue`, that path skips it. Put the update in the loop header or ensure every path changes the variant.
