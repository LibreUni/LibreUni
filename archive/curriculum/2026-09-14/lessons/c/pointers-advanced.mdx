# Advanced Pointers, Qualifiers, and Callbacks

Pointer syntax becomes difficult when several independent contracts are compressed into one declaration. Expand each declaration from the identifier outward, then ask which object can be mutated, who owns it, and how long the value remains usable.

## Pointer-to-pointer interfaces

An `int **out` parameter lets a function write a pointer value into a caller-owned pointer object. This is useful for allocation and replacement, but it creates two validity obligations: the outer pointer must designate a live pointer object, and the new inner pointer must follow its own ownership contract.

```c
int make_buffer(size_t n, char **out) {
    char *buffer = malloc(n);
    if (buffer == NULL) return -1;
    *out = buffer;       /* transfer ownership to caller */
    return 0;
}
```

The function must not write `*out` on failure unless the API says so. A caller can initialize `char *buffer = NULL`, call the function, and free it only after successful ownership transfer.

## Function pointers and callbacks

A function pointer is a value designating a function with a compatible type. A callback API must specify when the callback runs, what arguments mean, whether it may re-enter the caller, and whether the callback remains registered after the call.

```c
typedef void (*event_handler)(int event, void *context);

struct listener {
    event_handler handler;
    void *context;       /* borrowed or owned — document which */
};
```

In interrupt or signal context, ordinary application callbacks may be unsafe because they allocate, block, take non-reentrant locks, or access non-atomic shared state. A safer design records a small event and processes it in a normal context.

## Representation and aliasing boundaries

`void *` can carry an object pointer and be converted back to the original compatible type, but it is not a license to ignore alignment, lifetime, or effective-type rules. Casting a pointer changes the type used for access; it does not change the bytes into a new object. Use `memcpy` or a documented serialization format for representations that cross trust or ABI boundaries.

### Diagnostic solutions

1. Read-only data through a mutable local pointer; fixed pointer to mutable int; fixed pointer to read-only int, respectively.
2. The design needs a happens-before rule: wait for active callbacks, use reference counting/epochs, or forbid unregister during dispatch. Merely setting the function pointer to null can race with a call.
3. The callback may later dereference a dangling pointer. Copy owned state, extend its lifetime, or unregister before destruction.
4. Padding, alignment, endianness, representation, and strict aliasing can all differ. Parse fields explicitly or use a specified serialization layout.
