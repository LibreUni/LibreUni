# Pointers, Objects, and Indirection

Model a pointer as a value that can designate an object of a compatible type (or the null pointer value). It is not automatically a valid address, an ownership token, or a bounds descriptor. Correct pointer use requires three questions: what object is designated, is that object alive, and is the operation permitted for its type and position?

## Address and indirection

`&object` produces a pointer to an object. `*pointer` accesses the designated object, but dereferencing a null, dangling, or otherwise invalid pointer is undefined behavior. A pointer may be copied; copying the pointer creates an alias, not a copy of the object.

## Null, lifetime, and ownership

The null pointer value compares unequal to every valid pointer to an object, but its representation is implementation-defined. Check a pointer before dereferencing it when null is a permitted state. A pointer to a local object becomes dangling when the block exits; a pointer to freed storage becomes dangling when `free` ends the allocation's lifetime. Neither case is repaired by the bytes still appearing in memory.

Ownership is a separate contract. A borrowed pointer may be used for a call but not freed; an owning pointer is responsible for release; a transferred pointer changes responsibility at a documented point. C does not enforce these roles, so name them in APIs and comments.

## Pointer arithmetic boundaries

For an array object, `p + i` is valid only within the array or one past it, and `*(p + i)` requires an actual element. Adding an arbitrary integer to a pointer into a struct, a string literal, or unrelated storage is not a portable way to inspect bytes. Use `unsigned char *` for permitted object-representation inspection and respect alignment and lifetime rules when converting back.

## Transfer exercises

1. Draw the objects and aliases for `int a = 1; int *p = &a; int **q = &p;`.
2. Explain why `p = NULL` does not make another alias to the old object safe.
3. Give a valid use of a one-past pointer and an invalid use.
4. Review a function that returns a pointer to a local array and repair its ownership contract.

### Diagnostic solutions

1. `a` is an int; `p` is a pointer object designating a; `q` is a pointer object designating p. `**q` accesses a.
2. Nulling one pointer changes only that pointer object. Other aliases may still designate a live or dead object; lifetime and ownership must be managed independently.
3. Use it as a loop sentinel or compare it with another pointer in the same array. Do not dereference it or form a pointer beyond it.
4. Let the caller provide storage, allocate and document transfer of ownership, or return a static/managed object with an explicit concurrency and lifetime contract.
