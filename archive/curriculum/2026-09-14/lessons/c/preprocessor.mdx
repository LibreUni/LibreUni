# The C Preprocessor and Translation Boundaries

Preprocessing is a text-and-token transformation that runs before the compiler parses the resulting translation unit. It does not understand C types or function contracts. That power is useful for portability and repeated declarations, but it also makes source review and debugging harder.

## Inclusion and guards

`#include "project.h"` and `#include <system.h>` select different search policies, but neither is a module system. A header should expose declarations and use a guard or a supported equivalent:

```c
#ifndef SENSOR_H
#define SENSOR_H

int sensor_read(void);

#endif
```

The guard prevents repeated inclusion within a translation unit. It does not prevent two different headers from declaring incompatible interfaces, and it does not make definitions in a header safe to duplicate.

## Macro expansion and hygiene

Parenthesize both parameters and the whole replacement:

```c
#define SQUARE(x) ((x) * (x))
```

Even this macro evaluates `x` twice, so `SQUARE(i++)` is unsafe. A typed function avoids repeated side effects. Multi-statement macros require a `do { ... } while (0)` wrapper and careful temporary naming, but a function is usually clearer.

Object-like macros are appropriate for conditional compilation or a compile-time token. Prefer an enumeration for related integral constants and a `const` object when a typed addressable value is needed.

## Conditional compilation and evidence

`#if`, `#ifdef`, and predefined macros can select platform code, but each branch is a separate program that needs compilation and tests. Do not treat an unbuilt platform branch as portable. Keep the platform-specific surface small behind a common interface.

`#` stringifies a macro argument and `##` pastes tokens; use them only when the generated name is easier to audit than the explicit alternatives. Generated identifiers can hide spelling errors and make tooling less effective.

## Transfer exercises

2. Give a reason an include guard cannot cure a function definition duplicated across two translation units.
3. Choose between a macro and an inline function for a bounds-checked min operation and state the evaluation policy.
4. Explain why every conditional-compilation branch needs a build/test path.

### Diagnostic solutions

1. `2 + 3 * 2 + 3` evaluates to 11, not 25. Parenthesize the parameter and result.
2. Guards act within one preprocessed translation unit. The linker still sees duplicate external definitions from different units.
3. Choose a typed function when arguments may have side effects or types matter. Document conversions and evaluate each argument once.
4. The preprocessor removes the other branch before parsing, so an unbuilt branch can contain syntax, type, or behavioral defects that no current build detects.
