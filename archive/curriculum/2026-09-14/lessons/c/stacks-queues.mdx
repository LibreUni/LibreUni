# Stacks, Queues, and Circular Buffers

An abstract data type specifies observable operations and their laws. A stack exposes last-in, first-out behavior; a queue exposes first-in, first-out behavior. An array, linked list, or ring buffer is an implementation choice that must preserve those laws and report capacity failures explicitly.

## Stack contract

For a bounded stack, maintain `0 <= top <= capacity`; the next push writes at `items[top]` and increments `top`, while pop decrements first and reads the item. Returning `-1` as an empty sentinel is valid only when `-1` is excluded from the element domain; otherwise return a status and an output value.

## Queue contract and wraparound

A ring buffer with `head`, `tail`, and `count` can use:

```c
items[tail] = value;
tail = (tail + 1) % capacity;
++count;
```

Enqueue requires `count < capacity`; dequeue requires `count > 0`. The modulo operation is safe only when `capacity > 0`, and the count update must occur exactly once on successful operations. Test the sequence that fills, drains, and refills the buffer.

## Transfer exercises

1. Trace head, tail, and count for capacity 4 through enqueue A, B, dequeue, enqueue C, D, E.
2. State the invariant for an array stack and prove pop returns the last pushed value not yet removed.
3. Give a safe API for popping values when every integer is valid.
4. Compare a ring buffer with a linked queue for a fixed-capacity producer/consumer workload.

### Diagnostic solutions

1. Start `(0,0,0)`, then `(0,1,1)`, `(0,2,2)`, dequeue to `(1,2,1)`, enqueue C `(1,3,2)`, D `(1,0,3)`, E `(1,1,4)`; the final enqueue is valid only if capacity was four.
2. `top` is the number of live elements in `items[0..top)`. Push extends the prefix; pop reads `items[top-1]` before shrinking it.
3. `int stack_pop(struct stack *, int *out)` returning a status; write `*out` only on success.
4. A ring buffer avoids allocation and has predictable bounded storage; a linked queue grows but adds allocation, pointer, and reclamation costs. Choose based on capacity and failure policy.
