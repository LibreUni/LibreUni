# C Types, Tokens, and Integer Boundaries

The compiler does not see “lines of code”; it sees preprocessing tokens that become declarations, expressions, and statements. A declaration gives an object a type, and the type affects representation, conversions, permitted operations, and the proof needed before an operation is safe.

## Tokens, declarations, and types

Identifiers are case-sensitive. A declaration such as `const unsigned long count;` combines a base type, qualifiers, and a name; its semantics are not determined by a variable's apparent value. Scope and linkage determine where a name can be used and whether separate declarations denote one entity.

Use `<stdint.h>` types when a width matters, `<stddef.h>` for sizes, and `<limits.h>` for implementation-provided limits. `char` may be signed or unsigned; do not use it as a portable signed 8-bit integer.

## Promotions and conversions

Types narrower than `int` are often promoted before arithmetic. Mixed signed/unsigned expressions can convert a negative signed value to a large unsigned value. Narrowing conversions can discard information. Make the intended type explicit and validate ranges before converting external data.

## Overflow and limits

Unsigned arithmetic is defined modulo 2^N for its width. Signed overflow is undefined behavior; the compiler may assume it never occurs. Check before addition, subtraction, multiplication, or narrowing when values originate outside the proven range.

### Diagnostic solutions

1. The standard specifies minimum ranges, not a single size for every implementation. Use fixed-width types or `sizeof`/limits when the requirement is explicit.
2. Require `value <= UINT32_MAX` before the conversion; the source must also be a valid uint64_t on the implementation.
3. The negative int is converted to size_t, an unsigned type, producing a large value modulo the size_t range; later allocation or loop logic may fail.
4. Implementation-defined behavior is chosen and documented by the implementation; unspecified behavior permits one of several choices without documentation; undefined behavior imposes no requirements.
