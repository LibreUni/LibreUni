# Command and State: Requests and Lifecycles

Command turns an action into a value that can be queued, logged, retried, authorized, or undone. State makes a lifecycle explicit so behavior can vary by current state without scattered conditionals. Together they are useful for workflows, but they do not remove the need for idempotency or transition invariants.

## Commands and receivers

A command should carry intent and validated data, not an arbitrary object graph. An invoker decides when to run it; a receiver owns the domain operation. If a command is persisted, version its schema and define how old commands are interpreted.

## State transitions

Write a transition table before creating state subclasses:

| Current | Event | Next | Rejection |
| --- | --- | --- | --- |
| pending | approve | approved | unauthorized |
| pending | cancel | cancelled | policy violation |
| approved | ship | shipped | inventory unavailable |
| cancelled | approve | — | illegal transition |

The table makes illegal transitions testable and reveals whether an event is a command, a domain fact, or both. State objects can localize behavior, but a giant hierarchy can obscure the complete lifecycle.

## Transfer exercises

1. Choose fields for an auditable refund command.
2. Explain why an invalid state transition should be observable rather than silently ignored.
3. Give an undo policy for a command with an external side effect.
4. Distinguish an event fact from a command request.

### Diagnostic solutions

1. Command ID, actor/authorization context, target, amount/currency, reason, creation time, expected version, and idempotency policy.
2. Silent ignore can make clients believe work happened and hides contract violations; return a typed result and audit the rejection where appropriate.
3. External effects may be non-reversible; use a compensating command and document its limits rather than pretending to restore history.
4. A command asks the system to act; an event records that something happened. Commands may fail or be retried; events need stable identity and consumer semantics.
