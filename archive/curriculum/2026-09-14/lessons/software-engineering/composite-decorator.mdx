# Composite and Decorator: Uniform Structure and Wrapping

Composite represents a tree where leaves and groups share a useful operation. Decorator wraps one component to add behavior while preserving the component interface. Both can make clients uniform, but Composite models structure and Decorator models layered responsibility.

## Composite invariants

A composite tree needs an ownership and cycle policy. If adding a child makes the child reachable from its ancestor, reject cycles; decide whether a child can have multiple parents; define whether an empty group has size zero and whether deletion cascades. Uniform methods are useful only when the operation has coherent meaning for both leaves and composites.

## Decorator layers

A decorator forwards the component contract and adds a focused behavior:

```python
class TimedReader:
    def __init__(self, inner, clock): self.inner, self.clock = inner, clock
    def read(self, key):
        start = self.clock()
        value = self.inner.read(key)
        record_latency(self.clock() - start)
        return value
```

Decorator order can be observable: caching before authorization is unsafe if cache keys ignore identity; retrying before timeout changes the effective deadline. Test composition order and failure propagation.

## Transfer exercises

4. Choose Composite or Decorator for a document with optional encryption layers.

### Diagnostic solutions

1. Following child links from any node never revisits a node and terminates; ownership/parent policy is explicit.
2. Authorization must happen before a shared cache lookup unless the cache is partitioned by principal and the policy is proven equivalent.
3. Clients written for the original result cannot consume the changed type; introduce a new port or preserve the original contract.
4. Decorator: encryption is layered behavior around one document stream, not a part-whole tree. State key ownership and error behavior.
