# Template Method and Iterator: Stable Algorithms and Traversal

Template Method fixes an algorithm's control skeleton while allowing selected steps to vary. Iterator exposes sequential access without requiring clients to know the collection representation. Both are valuable only when the stable part is real and the extension contract is precise.

## Template Method

A template might validate input, acquire a resource, perform a variable step, and release the resource. The base algorithm owns ordering and cleanup; subclasses fill a narrow hook. The hook contract must prevent a subclass from skipping required validation or leaking resources. Composition can be preferable when variation does not need inheritance.

## Iterator contracts

An iterator needs a definition of order, exhaustion, and mutation. Does `next()` return a value or raise a sentinel? Does modifying the collection invalidate the iterator, fail-fast, or provide a snapshot? A list iterator and a tree iterator may share a `next` shape while having different ordering guarantees; the interface must say which guarantees are common.

## Transfer exercises

1. Give a Template Method hook that must not be allowed to skip cleanup.
2. Compare a snapshot iterator with a fail-fast iterator for a live dashboard.
3. State whether an iterator promises sorted order for a hash set.
4. Explain why exposing an internal index can leak representation.

### Diagnostic solutions

1. A processing hook between acquisition and release; the template owns a `finally`/cleanup path so subclasses cannot bypass it.
2. Snapshot gives repeatable view at memory cost; fail-fast reveals concurrent mutation but requires callers to restart or coordinate. Choose from product semantics.
3. No, unless the collection's interface explicitly promises an ordering. Hash iteration order is not a sorted guarantee.
4. An array index assumes contiguous storage and becomes invalid after reallocation or a linked/tree representation; the iterator protocol preserves abstraction.
