# Unit Testing as Contract Probing

A unit test is a repeatable experiment at a chosen boundary. “Unit” does not universally mean one method or one class; it means the test isolates the behavior enough that a failure has a useful diagnosis and the setup does not depend on unrelated infrastructure.

## Partitions and boundaries

Partition inputs by behavior: valid/invalid, empty/nonempty, below/at/above a limit, authorized/unauthorized, dependency success/timeout. Choose representatives at boundaries where the implementation is likely to change branch or representation. A test count is not coverage of the contract.

## Test independence and diagnosis

A unit test should control nondeterminism such as time, randomness, and external responses when those are not the behavior under test. Avoid asserting private call sequences unless the sequence is part of the contract. A test that fails because an internal helper was renamed is high-coupling evidence; a test that misses a broken authorization rule is weak evidence.

The FIRST mnemonic (fast, isolated, repeatable, self-checking, timely) is a heuristic. A slower integration test may be the correct test for a transaction boundary; label the boundary instead of forcing every test into a taxonomy.

## Transfer exercises

1. Create partitions for a password policy requiring 12–64 characters.
2. Identify a mock assertion that tests implementation rather than behavior.
3. Explain why a test can be isolated yet still weak.
4. Add a property to a test of a reversible encode/decode pair.

### Diagnostic solutions

1. Below 12, 12, interior, 64, above 64; add encoding/byte-length and forbidden-character partitions if specified.
2. “assert helper_x called once” is implementation-focused unless the call is a required observable side effect; assert the resulting behavior or emitted event instead.
3. It may cover only a happy path, assert the wrong result, or use unrealistic dependencies. Isolation is a setup property, not correctness evidence.
4. For valid values, `decode(encode(x)) == x`; define invalid input and canonicalization separately.
