This comprehensive examination evaluates computer systems engineering across four integrated architectural domains: bit representation and datapath synthesis, pipelined execution and hazard control, multi-level memory hierarchies and virtual translation, and multicore parallelism with DMA device invariants.

Every numerical derivation requires explicit units and algebraic models; every control or pipeline schedule requires stage occupancy tables with explicit signals; and every systems design claim requires a falsifiable failure analysis.

## Examination Questions

<ExamQuestion id="q-arch-exam-isa-datapath" points={25} title="Part A — Representation, ISA Bitfields, and Datapath Critical Path">

A 32-bit RISC processor features fixed 4-byte instructions, byte-addressed memory, and 32 general-purpose registers (`x0` hardwired to zero). An immediate branch instruction encodes a signed 12-bit displacement in bytes, two 5-bit source register operands, and an opcode. The branch target is calculated relative to the address of the sequential instruction (`PC + 4`).

1. Derive the representable range of the signed 12-bit displacement in bytes. Show the exact two's-complement bit pattern and 32-bit sign extension for an instruction located at `0x1000` with displacement `-16` (`0xFF0`), and compute the resulting branch target address in hexadecimal.
2. Define the architectural transition for a signed 16-bit halfword load `lh rd, imm(rs1)`. State the alignment rule, byte assembly order, sign extension into `rd`, PC update, and destination register invariant when a page fault occurs.
3. A systems programmer casts an untrusted signed 32-bit user length `int32_t len` to an unsigned allocation size `uint32_t size = (uint32_t)len` before checking `if (size < BUFFER_MAX)`. Identify the boundary value that bypasses this check, and state the exact sequence of validation checks required.
4. The single-cycle datapath has component latencies: instruction memory fetch 280 ps, register file read 160 ps, ALU 220 ps, data memory 420 ps, write-back multiplexer 70 ps, and clock/setup overhead 100 ps. Construct the control signal truth table (`RegWrite`, `MemRead`, `MemWrite`, `ALUSrc`, `ResultSrc`, `PCSrc`) for `add`, `lw`, `sw`, `beq`, and `jal`. Compute the load critical path and maximum clock frequency.

<MarkingScheme points={25}>
- **Signed Range and PC Target Derivation (6 pts):**
  - Range: $[-2^{11}, 2^{11}-1] = [-2048, 2047]$ bytes.
  - 12-bit encoding of $-16$: `0xFF0` (binary `1111_1111_0000`). Sign extension to 32 bits replicates bit 11 across bits 31..12 yielding `0xFFFFFFF0`.
  - Target calculation: Base address is `PC + 4 = 0x1004`. Target is `0x1004 + 0xFFFFFFF0 = 0x0FF4` modulo $2^{32}$. (Full credit requires `0x0FF4`; computing `0x0FF0` without incrementing PC receives half credit).
- **Architectural Load Contract and Fault Invariant (6 pts):**
  - Natural halfword alignment check: `(rs1 + imm) & 1 == 0`.
  - Little-endian byte assembly: `val = mem[addr] | (mem[addr+1] << 8)`.
  - Sign extension: replicates bit 15 across bits 31..16.
  - Fault invariant: If translation fails or page is absent, an architectural exception traps with `epc = PC`. Register `rd` must not be updated; no partial byte writes or destination register corruption can occur.
- **Conversion Vulnerability and Checked Guard (5 pts):**
  - Casting `-1` (`0xFFFFFFFF`) to unsigned yields $4{,}294{,}967{,}295$. If checked against a buffer limit using signed arithmetic, or if multiplied by element size $S$, integer wraparound can allocate a tiny buffer while a subsequent copy writes $4\text{ GB}$.
  - Safe check sequence: (1) verify $len \ge 0$, (2) check $len \le \text{MAX\_ELEMENTS}$, (3) compute allocation bytes with checked multiplication overflow detection.
- **Datapath Control Signals and Critical Path (8 pts):**
  - Control table:
    - `add`: `RegWrite=1`, `MemRead=0`, `MemWrite=0`, `ALUSrc=0` (reg), `ResultSrc=0` (ALU), `PCSrc=0`.
    - `lw`: `RegWrite=1`, `MemRead=1`, `MemWrite=0`, `ALUSrc=1` (imm), `ResultSrc=1` (mem), `PCSrc=0`.
    - `sw`: `RegWrite=0`, `MemRead=0`, `MemWrite=1`, `ALUSrc=1` (imm), `ResultSrc=X`, `PCSrc=0`.
    - `beq`: `RegWrite=0`, `MemRead=0`, `MemWrite=0`, `ALUSrc=0` (reg), `ResultSrc=X`, `PCSrc=Zero`.
    - `jal`: `RegWrite=1`, `MemRead=0`, `MemWrite=0`, `ALUSrc=X`, `ResultSrc=2` (PC+4), `PCSrc=1`.
  - Load critical path summation: $T = 280 + 160 + 220 + 420 + 70 + 100 = 1250\text{ ps}$.
  - Maximum frequency: $f_{\max} = 1 / 1250\text{ ps} = 800\text{ MHz}$. Full credit notes that faster ALU or branch instructions do not reduce the single-cycle clock period because the period is bounded by the longest path.
</MarkingScheme>

</ExamQuestion>

<ExamQuestion id="q-arch-exam-pipeline-hazards" points={25} title="Part B — Pipeline Hazards, Interlock Forwarding, and Branch Squashes">

Consider a classic 5-stage RISC pipeline consisting of Instruction Fetch (IF), Instruction Decode / Register Read (ID), Execute / Address Calc (EX), Memory Access (MEM), and Register Write-Back (WB). ALU-to-ALU forwarding is supported from `EX/MEM` and `MEM/WB` back to the EX stage. Branches resolve in the EX stage with a default predict-not-taken scheme.

<PlantUML code={`@startuml
rectangle "IF\nPC+4" as IF
rectangle "ID\nDecode / Regs" as ID
rectangle "EX\nALU / Branch" as EX
rectangle "MEM\nData RAM" as MEM
rectangle "WB\nRegFile Write" as WB

IF --> ID : IF/ID
ID --> EX : ID/EX
EX --> MEM : EX/MEM
MEM --> WB : MEM/WB

EX ..> ID : Branch Flush (squash IF/ID, ID/EX)
MEM ..> EX : Forward ALU result (EX/MEM)
WB ..> EX : Forward Load/ALU result (MEM/WB)
@enduml`} />

Execute the following 5-instruction program sequence starting with `I1` fetched in cycle 1:
```text
I1: lw   r1, 0(r2)
I2: add  r3, r1, r4
I3: sub  r5, r3, r6
I4: beq  r5, r0, target
I5: or   r7, r8, r9
```
Assume `r2 = 0x2000`, `r4 = 10`, `r6 = 25`, memory at `0x2000` contains `15`, and the branch `beq` evaluates to taken (`15 + 10 - 25 == 0`).

1. Construct the complete cycle-by-cycle stage occupancy table from cycle 1 through cycle 9.
2. Identify the exact cycle in which a load-use hazard bubble is inserted into the pipeline, which stage holds the bubble, and which stage registers are stalled.
3. Trace every forwarding event, stating the source pipeline register (`EX/MEM` or `MEM/WB`), destination ALU input operand, and cycle number.
4. Detail the branch squash mechanism when `I4` resolves taken in EX. State which cycle the squash occurs, which instructions are flushed, which control signals are altered, and which cycle the target instruction enters IF.

<MarkingScheme points={25}>
- **Cycle-by-Cycle Pipeline Schedule (10 pts):**
  - Cycle 1: `I1` in IF.
  - Cycle 2: `I1` in ID; `I2` in IF.
  - Cycle 3: `I1` in EX; `I2` in ID; `I3` in IF.
  - Cycle 4 (Load-Use Stall): `I1` in MEM; `I2` stalled in ID; `I3` stalled in IF; bubble (NOP) injected into EX.
  - Cycle 5: `I1` in WB; `I2` in EX (forwarding `r1` from MEM/WB); `I3` in ID; `I4` in IF.
  - Cycle 6: `I2` in MEM; `I3` in EX (forwarding `r3` from EX/MEM); `I4` in ID; `I5` in IF.
  - Cycle 7: `I2` in WB; `I3` in MEM; `I4` in EX (forwarding `r5` from EX/MEM); `I5` in ID.
  - Cycle 8 (Branch Flush): `I3` in WB; `I4` in MEM; `target` in IF; `I5` flushed.
  - Cycle 9: `I4` in WB; `target` in ID.
- **Load-Use Bubble and Interlock Control (5 pts):**
  - In cycle 4, the hazard detection unit observes `ID/EX.MemRead == 1` and (`ID/EX.rd == IF/ID.rs1 || ID/EX.rd == IF/ID.rs2`).
  - Action: Assert stall on `PC` and `IF/ID` registers (freezing `I3` and `I2`), while clearing `ID/EX` control signals to 0 (`NOP` bubble enters EX in cycle 4).
- **Forwarding Path Trace (5 pts):**
  - Cycle 5: `I1` (`lw`) is in WB; data forwarded from `MEM/WB` register to EX ALU input operand `A` for `I2` (`add`).
  - Cycle 6: `I2` (`add`) is in MEM; computed result forwarded from `EX/MEM` register to EX ALU input operand `A` for `I3` (`sub`).
  - Cycle 7: `I3` (`sub`) is in MEM; computed result forwarded from `EX/MEM` register to EX ALU input operand `A` for `I4` (`beq`).
- **Branch Squashing and Target Redirection (5 pts):**
  - At cycle 7 in EX, `beq` calculates `r5 - r0 == 0`, asserting the branch taken condition.
  - Recovery: At the end of cycle 7, the controller asserts `Flush` on `IF/ID`, clearing the valid bit of `I5` (`or`) so it becomes a bubble in cycle 8 and cannot write registers in WB.
  - Target PC enters IF in cycle 8. Older instructions `I1`, `I2`, `I3`, and `I4` retire with exact architectural state.
</MarkingScheme>

</ExamQuestion>

<ExamQuestion id="q-arch-exam-memory-hierarchy" points={25} title="Part C — Multilevel Cache AMAT, Index Mapping, and Virtual Memory">

A 64-bit computer system utilizes a 32 KiB 4-way set-associative L1 data cache with 64-byte cache lines and 32-bit physical addresses. Memory access times and miss rates are:
- L1 data cache: hit time $t_{L1} = 1\text{ cycle}$, local miss rate $m_{L1} = 0.06$.
- L2 unified cache: hit time $t_{L2} = 8\text{ cycles}$, local miss rate $m_{L2} = 0.15$.
- Main memory (DRAM): access penalty $t_{\mathrm{mem}} = 90\text{ cycles}$ after an L2 miss.

The virtual memory subsystem uses 4 KiB pages and a 4-level page table structure with 512 entries (8 bytes each) per page-table page, supporting a 48-bit virtual address space.

1. Decompose the 32-bit physical address into offset, set-index, and tag bitfields for the L1 cache. Map the two physical addresses `0x12345678` and `0x12347678` to their respective set index and tag, and determine if they contend for the same cache set.
2. Calculate the Average Memory Access Time ($\mathrm{AMAT}$) under the serial memory hierarchy model. Then calculate the global L2 miss rate. Demonstrate quantitatively what error occurs if an engineer mistakenly treats the 15% local L2 miss rate as a global access fraction.
3. For the 48-bit virtual address `0x123456789abc`, derive the bitfield width and numerical decimal value of the four page-table indexes ($L_4, L_3, L_2, L_1$) and the page offset.
4. Detail the architectural copy-on-write (COW) fault handling sequence when a child process attempts a store to a shared physical frame after `fork()`. Specify all page-table permission adjustments, physical frame allocation steps, and TLB invalidation requirements.

<MarkingScheme points={25}>
- **L1 Cache Geometry and Address Decomposition (7 pts):**
  - Line offset: $\log_2(64) = 6\text{ bits}$ (`bits [5:0]`).
  - Number of sets: $S = 32768 / (64 \times 4) = 128\text{ sets}$.
  - Set index: $\log_2(128) = 7\text{ bits}$ (`bits [12:6]`).
  - Tag: $32 - 6 - 7 = 19\text{ bits}$ (`bits [31:13]`).
  - Mapping:
    - `0x12345678`: Low 13 bits are `0x1678` = binary `1_0110_0111_1000`. Offset is `bits [5:0]` = `0b111000 = 0x38` (56). Index is `bits [12:6]` = `0b01011001 = 89` (`0x59`). Tag is `0x12345 >> 1` = `0x91A2`.
    - `0x12347678`: Low 13 bits are `0x1678`. Offset = `0x38` (56). Index = `89` (`0x59`). Tag = `0x91A3`.
    - Both addresses share set index 89 and compete for ways in set 89.
- **Multilevel AMAT and Miss Rate Analysis (7 pts):**
  - Serial model: $\mathrm{AMAT} = t_{L1} + m_{L1}(t_{L2} + m_{L2} \cdot t_{\mathrm{mem}}) = 1 + 0.06(8 + 0.15 \times 90) = 1 + 0.06(8 + 13.5) = 1 + 0.06(21.5) = 2.29\text{ cycles}$.
  - Global L2 miss rate: $m_{\mathrm{global},2} = m_{L1} \times m_{L2} = 0.06 \times 0.15 = 0.009 = 0.9\%$.
  - Treating 15% as global: $\mathrm{AMAT}_{\mathrm{err}} = 1 + 0.06 \times 8 + 0.15 \times 90 = 1 + 0.48 + 13.5 = 14.98\text{ cycles}$.
  - Full credit notes that L2 misses cannot physically exceed the 6% of memory requests that missed L1 and reached L2.
- **Virtual Address 4-Level Page Table Decomposition (5 pts):**
  - 4 KiB pages require 12 offset bits (`bits [11:0]`).
  - Remaining 36 bits divide into four 9-bit levels ($\log_2(512) = 9$): $L_4$ (`[47:39]`), $L_3$ (`[38:30]`), $L_2$ (`[29:21]`), $L_1$ (`[20:12]`).
  - Virtual address `0x123456789abc`:
    - Offset: `0xabc` (decimal 2748).
    - $L_1$: `bits [20:12]` = `0x189` (decimal 393).
    - $L_2$: `bits [29:21]` = `0x0B3` (decimal 179).
    - $L_3$: `bits [38:30]` = `0x0D1` (decimal 209).
    - $L_4$: `bits [47:39]` = `0x024` (decimal 36).
- **Copy-On-Write Fault Sequence and Invariants (6 pts):**
  - Hardware detects store instruction accessing page with `Valid=1` and `Write=0`, raising a page fault trap.
  - OS handler inspects VMA; verifies page is marked COW with reference count $> 1$.
  - Handler allocates a fresh physical frame, copies the 4 KiB data from the shared frame, updates the faulting process's PTE with the new physical frame number and sets `Write=1`.
  - Decrements reference count on the original frame.
  - Crucial: Executes local TLB invalidation (`invlpg` / `sfence.vma`) for that virtual address before returning from exception handler to retry the store instruction.
</MarkingScheme>

</ExamQuestion>

<ExamQuestion id="q-arch-exam-parallel-systems" points={25} title="Part D — Amdahl Scaling, DMA Ownership Invariants, and Systems Bottlenecks">

A server node executes an image processing workload across a shared-memory multicore architecture with peripheral DMA accelerators.

1. A compute kernel is measured to have 90% parallelizable work ($f = 0.90$) and 10% strictly serial synchronization work. Calculate ideal Amdahl speedup for 2, 4, 8, 16, and an infinite number of processor cores.
2. The kernel processes high-throughput sensor streams via a network interface card using DMA descriptor rings. Construct the complete ownership state lifecycle for a network transmit buffer across states: `FREE`, `READY`, `IN_FLIGHT`, `DONE`, and `RECLAIMED`. State the explicit memory barriers and ownership handoffs required.
3. Contrast cache-coherent DMA with non-coherent DMA architectures. Detail what software cache operations must be performed before a device reads from a buffer and after a device writes to a buffer on a non-coherent architecture.
4. An autonomous device driver developer implements a software timeout: if a DMA transaction does not report completion within 100 ms, the driver marks the buffer `FREE` and reallocates it to another user process. Formulate the concrete failure trace demonstrating how this naive timeout introduces a memory corruption vulnerability, and state the hardware/IOMMU invariant required to prevent it.

<MarkingScheme points={25}>
- **Amdahl Speedup Limits (6 pts):**
  - Amdahl formula: $S_P = \frac{1}{(1-f) + f/P}$ with $f = 0.90$.
  - $P = 2$: $1 / (0.10 + 0.90/2) = 1 / 0.55 = 1.82\times$.
  - $P = 4$: $1 / (0.10 + 0.90/4) = 1 / 0.325 = 3.08\times$.
  - $P = 8$: $1 / (0.10 + 0.90/8) = 1 / 0.2125 = 4.71\times$.
  - $P = 16$: $1 / (0.10 + 0.90/16) = 1 / 0.15625 = 6.40\times$.
  - $P \to \infty$: $1 / 0.10 = 10.0\times$ theoretical maximum speedup.
- **DMA Buffer Ownership State Machine (7 pts):**
  - `FREE` $\to$ `READY`: CPU writes packet payload to buffer; executes release store barrier (`sfence` / memory barrier) to ensure all payload bytes reach memory before updating the descriptor ring head pointer.
  - `READY` $\to$ `IN_FLIGHT`: Peripheral fetches descriptor; claims ownership; initiates PCIe DMA read transactions. CPU must not touch buffer memory.
  - `IN_FLIGHT` $\to$ `DONE`: Peripheral finishes transfer; issues completion ring entry with status and generation token; asserts MSI-X interrupt.
  - `DONE` $\to$ `RECLAIMED`: CPU interrupt handler reads completion entry with acquire barrier; verifies generation token matches active request; claims read ownership of status and returns buffer to pool.
- **Cache Coherence vs Non-Coherent Cache Maintenance (6 pts):**
  - Cache-coherent DMA: Hardware bus snooping automatically enforces single-location serialization. CPU and device observe consistent memory without manual cache flush operations.
  - Non-coherent DMA:
    - Before device reads CPU buffer: CPU must perform **cache clean/flush** (write dirty cache lines back to physical RAM) so the device does not read stale RAM data.
    - Before CPU reads device-written buffer: CPU must perform **cache invalidate** on that address range so subsequent CPU loads read fresh data from physical memory rather than stale lines in L1/L2 cache.
- **Timeout Vulnerability and Quiescence Invariant (6 pts):**
  - Failure trace: The peripheral experiences a transient PCIe bus stall or internal firmware hang. After 100 ms, the CPU times out, marks the buffer `FREE`, and reallocates the physical frame to process $B$. At 105 ms, the peripheral recovers and completes the pending DMA write to that physical frame, silently corrupting process $B$'s memory (DMA use-after-free).
  - Required invariant: A timed-out buffer must never be reused or unmapped until the device is explicitly **quiesced** (bus mastering disabled via command register, engine reset asserted, or IOMMU mapping revoked and IOTLB flushed).
</MarkingScheme>

</ExamQuestion>
