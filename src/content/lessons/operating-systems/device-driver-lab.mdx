# Device-Driver Lab: A Defensible Virtio Queue

xv6-riscv revision 5 uses an eight-entry Virtio split queue. Each block request consumes a chain of three direct descriptors: command header, data buffer, and one-byte status. At most two requests can hold complete chains simultaneously because a third chain would require nine descriptors. The Virtio indirect-descriptor feature can represent those three elements behind one main-ring descriptor, raising the queue's descriptor-limited ceiling from two requests to eight when the device offers the feature.

The implementation target is not “make the benchmark number larger.” The target is a driver whose feature negotiation, publication order, request lifetime, completion validation, fault behavior, and measurements can be defended from traces.

This is an original LibreUni lab. It uses the licensed upstream teaching kernel and the public Virtio specification; it does not reproduce another course's assignment or solution.

### Non-negotiable invariants

Label these `I1`–`I10` in the memo and cite the code and test that establish each one.

| ID | Invariant |
| --- | --- |
| I1 | A feature is used only if the device offered it and the driver accepted it before `FEATURES_OK`. |
| I2 | One request owns either one indirect head descriptor or one complete direct chain, never a partial mixture. |
| I3 | Descriptor contents and the available-ring slot become device-visible before the published available index. |
| I4 | The data-buffer direction bit matches the operation: device-writable for reads, device-readable for writes. |
| I5 | `0 ≤ in_flight ≤ negotiated_queue_capacity`; full/empty remains correct across 16-bit index wrap. |
| I6 | A used-ring ID is bounds-checked before indexing driver metadata. |
| I7 | A request transitions to terminal state once; duplicate completion before reap is detected, not completed twice. |
| I8 | Completion state and status become visible before a waiter is woken; waiters recheck a predicate in a loop. |
| I9 | A descriptor, indirect table, status byte, and data buffer are not reused until device ownership ended and the waiter/reaper transferred ownership. |
| I10 | Timeout or process death does not imply device cancellation; no timed-out buffer is reused without specified quiescence/reset evidence. |

> **Defense boundary.** Standard split-ring used entries return a descriptor-chain head ID, not the driver's private generation counter. A software generation detects many lifecycle defects, but it cannot distinguish a malicious stale completion that arrives after the same head ID has been legitimately reused unless the protocol returns equivalent identity. Safety after reset therefore depends on verified device/queue quiescence, not generation numbers alone.

**Retrieval — before opening source.** Explain why eight main-ring entries permit only two baseline requests but as many as eight indirect requests. State the resource that still may reduce observed concurrency below eight.

<details>
<summary>Reveal the diagnostic answer</summary>

Baseline requests each require three direct descriptors, so `floor(8/3)=2` complete chains fit. An indirect request consumes one main descriptor that points to its private three-entry indirect table, so eight heads can fit if all other resources are available. Buffer-cache locking, process scheduling, available workload, device service time, and driver metadata can reduce observed concurrency; eight is a descriptor-capacity ceiling, not a throughput promise.

</details>

## Milestone A — isolate negotiation from queue layout

The baseline explicitly clears `VIRTIO_RING_F_INDIRECT_DESC` from the offered feature word. Refactor feature selection into a small testable decision whose output records whether indirect descriptors were accepted. Requirements:

1. read offered features;
2. reject features the driver does not implement;
3. retain `VIRTIO_RING_F_INDIRECT_DESC` only when the indirect path is compiled and offered;
4. write the accepted set;
5. set `FEATURES_OK` and re-read status as the baseline does; and
6. select direct fallback if the feature is absent.

The test harness must call the pure decision logic with synthetic feature words. Do not depend on undocumented QEMU command-line properties to simulate absence.

{/* Source tracking: Feature-negotiation ordering and the rule forbidding use of unaccepted features were verified against OASIS Virtio 1.3 Sections 2.2 and 3.1. */}

### Interface sketch, not a solution

```c
struct vdisk_features {
  uint32_t accepted;
  int indirect;
};

// Pure decision: no MMIO inside this function.
struct vdisk_features choose_vdisk_features(uint32_t offered,
                                            int indirect_build_enabled);
```

Tests must cover offered+enabled, offered+disabled, absent+enabled, and unknown offered bits. The MMIO initialization code remains responsible for status transitions.

**Application — reject force-indirect.** A mutant sets `VRING_DESC_F_INDIRECT` in descriptors whenever the build supports it, even when the device did not offer the feature. Which invariant fails before the first request, and what deterministic unit input exposes it?

I1 fails. Call the decision function with an offered word whose indirect bit is clear and build support enabled. The result must select direct fallback and must not set the indirect bit in `accepted`. A test that boots only one default QEMU instance may never exercise this case.

## Milestone B — implement one-head indirect requests

Add `VRING_DESC_F_INDIRECT` using the value defined by the Virtio specification. For each main descriptor slot, provide a persistent, device-visible, suitably aligned three-entry indirect table. It cannot live on a stack that disappears while the device owns it.

The indirect entries describe:

| Indirect entry | Buffer | Device direction |
| ---: | --- | --- |
| 0 | `struct virtio_blk_req` | device reads |
| 1 | `b->data` | device writes for block read; device reads for block write |
| 2 | one-byte status | device writes |

The main descriptor points to the indirect table, has length `3 × sizeof(struct virtq_desc)`, and sets `VRING_DESC_F_INDIRECT`. It must not also chain direct descriptors with `NEXT`. The used-ring ID remains the main descriptor index.

The xv6 kernel directly maps the relevant physical RAM, but the memo must still justify why each address given to the device is a valid DMA address in this teaching machine. “The C pointer compiled” is not evidence.

### Request resource model

Define resource acquisition as one transaction:

```text
reserve head slot
reserve per-head request metadata and indirect table
initialize command, data, and status entries
publish exactly one head
```

If any required resource is unavailable, release everything acquired in that attempt before sleeping/retrying. Partial descriptor ownership is forbidden by I2.

### Direct fallback remains first-class

Do not delete the direct-chain implementation. Factor common command/status setup while retaining two publication shapes. Both must satisfy the same lifecycle, status, wait, and trace interfaces. Run correctness and fault tests in both modes.

**Application — direction audit.** For an xv6 `bread`, write the flags for all three indirect entries. Repeat for `bwrite`. Explain the flag name from the device's perspective.

<details>
<summary>Reveal the flag audit</summary>

Entry 0 is device-readable and chains to entry 1. For `bread`, entry 1 sets device-write plus next because the device fills `b->data`; for `bwrite`, entry 1 sets next without device-write because the device consumes `b->data`. Entry 2 sets device-write because the device writes status. The main indirect descriptor uses the indirect flag and no direct-chain next flag.

</details>

Replace implicit combinations of `free[]`, `info[].b`, status, and `b->disk` with one auditable lifecycle. The exact enum names may differ, but every transition needs a lock, actor, and test.

State `PUBLISHED` is the device-ownership boundary. Rollback from it is prohibited without a device-defined cancel/reset/quiesce operation. A timeout may mark diagnostic state, stop admission, or fail-stop the teaching kernel; it may not transition directly to `FREE`.

### Metadata sketch

```c
enum req_state { REQ_FREE, REQ_RESERVED, REQ_BUILT,
                 REQ_PUBLISHED, REQ_COMPLETED, REQ_REAPED };

struct req_meta {
  enum req_state state;
  uint32_t generation;
  struct buf *buffer;
  uint64_t submit_time;
  uint64_t complete_time;
  unsigned char status;
};
```

This sketch is not a full implementation. Decide which fields are device-written, which lock protects transitions, when generation advances, and whether timing reads occur inside or outside the lock. Do not expose kernel pointers through a user-visible stats syscall.

### Completion validation order

The interrupt path must establish, in order:

1. interrupt status belongs to the device and is acknowledged as specified;
2. used-ring writes are visible before entries are consumed;
3. `id < NUM` before any `info[id]` access;
4. request state is `PUBLISHED`;
5. status is success before the buffer is declared valid to the caller;
6. state becomes `COMPLETED` and `b->disk` becomes false under the protocol lock;
7. waiters are woken after the predicate transition; and
8. `used_idx` advances exactly once per consumed used entry.

For an invalid ID, duplicate completion, or error status, a revision-5 teaching kernel may fail-stop with a stable diagnostic rather than implement full filesystem error propagation. It must not index out of bounds, report success, free owned DMA memory, or continue in an unknowable queue state.

**Transfer — generation limit.** A duplicate used entry for head 3 arrives after head 3 was completed, reaped, incremented to generation 18, and republished. The hardware used entry carries only ID 3. Can private `generation=18` prove that this completion belongs to generation 18?

<details>
<summary>Reveal the protocol boundary</summary>

No. The standard split-ring used entry does not return the private generation. The driver can detect a duplicate before reuse because state is no longer `PUBLISHED`, and test hooks can carry synthetic generation metadata, but a post-reuse stale ID is indistinguishable from the current request at this interface. The Virtio device contract and verified reset/quiescence prevent such late completions. Claiming generation alone solves the case overstates the protocol.

</details>

## Milestone D — publish with a provable happens-before edge

Virtio's split-ring sequence requires the driver to write descriptor contents and the available-ring entry, execute a suitable memory barrier, then update `avail.idx`; further ordering applies before notification checks/doorbells. Preserve the baseline's architecture-appropriate synchronization or replace it only with an equally justified primitive.

{/* Source tracking: The exact descriptor → available slot → barrier → available index → notification order was verified against OASIS Virtio 1.3 Section 2.7.13. */}

Create a test-only **device observer hook** at the publication boundary. When enabled, it snapshots the head descriptor, indirect entries, status poison, generation, and ring slot at the instant the driver is about to expose or has exposed `avail.idx`, according to the tested phase. The hook must verify that:

- every address and length is initialized;
- indirect chaining terminates correctly;
- status begins with a non-success poison value;
- direction flags match operation;
- head/generation metadata agrees with the ring slot; and
- no post-publication mutation occurs before completion.

The hook makes an early-publication mutant deterministic in QEMU, where accidental strong ordering might otherwise hide it. It supplements, rather than replaces, the source-level barrier argument.

### Ring-wrap proof obligation

`avail.idx` and `used.idx` are 16-bit monotonically increasing counters that wrap naturally. Physical ring slots use `% NUM`. Do not reduce the stored counters modulo `NUM` or compare only physical indices for full/empty.

Provide a pure ring arithmetic test that advances at least 65,540 logical submissions/completions without performing 65,540 disk operations. Check occupancy, slot selection, and empty/full transitions across both the eight-entry wrap and the 16-bit counter wrap.

<details>
<summary>Reveal the wrap oracle</summary>

For unsigned 16-bit producer and consumer counters with at most `NUM` outstanding, `(uint16)(producer - consumer)` yields occupancy across natural wrap. The harness should place counters near `65535`, submit and complete while never exceeding eight, and compare against a wider reference model. Any implementation that stores only `index % 8` cannot distinguish full from empty when the physical indices are equal.

</details>

## Milestone E — bounded observability without print storms

Add a fixed-size trace ring, for example 256 events, whose writer never allocates or sleeps in interrupt context. Each event should include only what is needed to reconstruct causality:

```text
sequence, r_time, cpu, event,
head, generation, operation, block,
avail_idx, used_idx, in_flight, status
```

Required event types: reserve, build, publish, sleep, interrupt, complete, wake, reap, rollback, and fault-detected. If the trace overwrites old entries, count drops/overwrites explicitly. Sequence numbers must let the reader detect missing events.

Add a snapshot interface for aggregate statistics:

- submitted/completed reads and writes;
- direct versus indirect submissions;
- descriptor-wait count and accumulated wait time;
- maximum in-flight requests;
- interrupts and completions drained per interrupt;
- request-time histogram or bounded sample sufficient for median/p95;
- error/fault-injection counters; and
- trace-overwrite count.

Copy a consistent snapshot to user space without holding the driver spinlock across `copyout`. One admissible pattern copies counters to a local kernel struct under the lock, releases the lock, then copies the local snapshot to user memory.

### Time units

Use raw `r_time()` deltas or calibrate them against the revision-5 timer interval. Do not label raw counter differences “nanoseconds” without a verified timebase. QEMU measurements describe the emulator and host run, not physical Virtio hardware.

**Application — trace completeness.** A trace contains `publish(g=7)`, `complete(g=7)`, and `publish(g=8)` for head 2, but no `reap(g=7)` or overwrite marker. Which invariant cannot be audited, even if all file data is correct?

## Milestone F — deterministic fault injection

Compile fault controls only in an explicit test build such as `VDISK_FAULT_TEST`. A normal build must not expose a user-controlled kernel fault surface. A test-only control call should arm one mode for the $n$th matching event, report whether it fired, and reset to a known disabled state at boot.

Required modes:

| Mode | Injection point | Correct observable outcome |
| --- | --- | --- |
| `SPURIOUS_WAKE` | while a request remains `PUBLISHED` | waiter wakes, rechecks, and sleeps again; no early return |
| `HOLD_COMPLETIONS` | before consuming selected used entries | request resources remain owned; other controller process can release hold |
| `BAD_USED_ID` | completion decoder | stable fail-stop before metadata indexing |
| `DUPLICATE_PRE_REAP` | feed one accepted ID again before reap | duplicate-state detection; no second wake/free/refcount update |
| `STATUS_ERROR` | completion status validation | no success/valid declaration; stable fail-stop or explicit propagated error |
| `PUBLISH_OBSERVER` | descriptor publication boundary | deterministic snapshot proves all fields precede publication |
| `DESCRIPTOR_PRESSURE` | hold completions while many readers submit | submitters block without partial ownership; release drains and wakes |
| `LATE_AFTER_TIMEOUT` | hold request past a diagnostic deadline | timeout never frees/reuses DMA-owned resources |

`HOLD_COMPLETIONS` needs a separate controlling process because the faulting worker may be asleep. Release must make forward progress without requiring the held worker to run first.

### Timeout policy for the core lab

Full Virtio reset is outside the core implementation. When a diagnostic deadline expires, choose one documented safe behavior:

- mark the device failed, stop new submissions, retain all in-flight resources, emit a bounded trace, and fail-stop; or
- retain ownership and wait for the test controller to release the held completion.

Returning an error while freeing the descriptor or buffer is forbidden. Recovery with queue reset is an extension only if it follows the negotiated transport procedure and proves that the device can no longer use old descriptors before release.

#### Upstream regression

Run in direct fallback and indirect modes:

```text

stressfs

```

`usertests -q` and `stressfs` must reach their normal completion markers. Revision-5 `grind` runs forever by design: drive it from an external harness for a declared duration or progress count, require continued `A`/`B` progress with no panic or failure diagnostic, then terminate that QEMU run from the harness. On a cumulative branch, run every earlier lab's accepted exit suite before and after this driver change. A passing upstream suite cannot substitute for a scheduler or synchronization invariant that the cumulative branch added.

#### Data integrity

Write deterministic per-block patterns to a temporary file larger than `NBUF`, wait for every write call to return, close the descriptors, terminate QEMU normally, and reboot the same image before reading/verifying in sequential and permuted block order. Use multiple child processes on disjoint files to create concurrent misses. A checksum mismatch must print file, logical block, expected generation, and observed checksum without dumping arbitrary data. This is a clean-restart integrity test, not a sudden-power-loss durability claim: revision 5 exposes no user-level flush contract for proving the latter.

#### Deterministic queue pressure

Arm `HOLD_COMPLETIONS`, launch at least eight disjoint cold reads, wait until the trace proves the queue reached its resource ceiling, release completions, and require every worker to finish with correct data. The direct build should expose its two-request descriptor ceiling; the indirect build should admit more than two and may reach eight. If another subsystem limits it, report that trace rather than fabricating a result.

#### Fault isolation

Run each fail-stop injection in a fresh throwaway `fs.img`/QEMU process. Match a stable diagnostic and verify that no later success marker appears. Rebuild the image for the next destructive case. Do not infer safety from a hung emulator.

#### Wrap and lifecycle unit tests

Exercise pure negotiation/ring functions without device I/O. Check every legal state edge and reject every illegal edge. Advance the reference counter across 65,535 and compare against a wider oracle.

- Device/emulator service is already saturated: inspect device utilization or completion rate versus queue depth.
- Extra queueing increases waiting without parallel service: split submit-to-dispatch and dispatch-to-complete times.
- A shared kernel/host lock or CPU is the bottleneck: compare `CPUS=1/3`, lock-wait instrumentation, and host CPU saturation.
- The workload hits another cache/path limit: inspect descriptor-wait count and actual block-driver submissions versus user operations.

The conclusion should identify which evidence discriminates mechanisms, not select one from intuition.

</details>

## Design memo

Use these headings; each section must cite code, trace events, or test output.

### Baseline and threat model

State the pinned ancestor, recorded lab-start commit, inherited cumulative changes, queue shape, device assumptions, trusted Virtio guarantees, and failures you inject. Distinguish a buggy driver, a spec-compliant device, and a device that violates the protocol.

### State and ownership proof

Define every request state, owner, lock, and legal edge. Prove I1–I10. Include the point after which rollback is forbidden and the point before which reuse is forbidden.

### Direct and indirect layouts

Draw both descriptor layouts, feature fallback, address lifetime, flags, alignment, and maximum in-flight calculation. Explain why the indirect table is persistent and device-visible.

### Ordering argument

Identify descriptor stores, available-ring store, barriers, index publication, notification, used-ring synchronization, terminal state, wake, and reap. A source line list without happens-before claims is incomplete.

### Failure analysis

For every injection, state detected symptom, contained state, resources intentionally retained, and why no unauthorized reuse occurs. Disclose that full reset/recovery is omitted.

### Evaluation

Present raw-data link/path, environment, repetitions, summary statistics, uncertainty, and competing explanations. Separate QEMU evidence from hardware claims.

### Residual risk

Name at least three untested assumptions, including post-reuse stale IDs, device reset, and filesystem error propagation. State the experiment or design work needed to reduce each risk.

## Defense questions

The reviewer chooses at least six and may change constants or point to a trace.

1. Why does one indirect descriptor increase request capacity without increasing main-ring size?
2. Which exact store publishes device ownership, and what must happen-before it?
3. Why is the data descriptor device-writable for a read but not a write?
4. What prevents a spurious wakeup from returning an incomplete buffer?
5. Where is a used ID checked, and what state remains safe when it is invalid?
6. Why can a private generation counter not identify a stale used entry after head reuse?
7. Which resources remain pinned after your diagnostic timeout, and what event would permit release?
8. How does the direct fallback prove that feature negotiation is not ceremonial?
9. Show the counter values immediately before and after 16-bit wrap; why is full distinguishable from empty?
10. Why can a descriptor be completed but not yet reusable?
11. Which test fails if completion state is written after `wakeup`?
12. What evidence shows indirect descriptors affected the bottleneck rather than only max in-flight?
13. If p95 worsens while throughput improves, which objective decides acceptance?
14. Which claim in the memo would become invalid on a noncoherent DMA platform?
15. What additional protocol is required to recover rather than fail-stop after a device timeout?
16. Which earlier-lab invariant is most exposed when a submitter sleeps for descriptors, and what regression trace proves this driver preserved it?

An answer may consult source and traces. Guessing an undocumented guarantee is worse than identifying the boundary.

- device uses an unoffered feature;
- user-visible success on nonzero device status;
- descriptor or buffer reuse while device ownership may remain;

## Extension work

Extensions are considered only after the core reaches 100-point behavior:

- implement Virtio queue reset when the feature/transport supports it, with proof that old DMA ownership ended;
- propagate block errors through buffer cache and filesystem without panic;
- negotiate event-index notification suppression and measure interrupt batching;
- implement packed virtqueues;
- add multiple queues with per-CPU submission while preserving fairness; or
- port the protocol to a noncoherent DMA model with explicit cache synchronization.

Each extension needs new mutants and failure oracles. Feature count is not quality evidence.

## Deliberate boundary and source trail

The core lab targets QEMU's Virtio MMIO block device and xv6-riscv revision 5. It improves descriptor capacity, observability, and lifecycle validation but deliberately stops at fail-stop handling for protocol corruption and timeout. It does not claim production recovery, hardware performance, IOMMU isolation, or a complete error-propagating storage stack.
